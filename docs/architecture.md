# Архитектура

Документ описывает, как устроено приложение изнутри: слои, модули, жизненный цикл
запуска, хранение данных и принятые ограничения. Рассчитан на того, кто будет
менять код.

## Общая картина

```
Браузер (web/index.html + app.js + styles.css)
        │  REST + SSE, токен сессии, только 127.0.0.1
        ▼
app/server.py            HTTP-транспорт, статика, SSE, диспетчеризация
├── app/api/dispatch.py  обработчики REST API
├── app/auth.py          аккаунты и сессии
        │
        ├── app/spec.py          нормализация и проверка проекта
        ├── app/workspace.py     политика рабочих областей
        ├── app/tools.py         инструменты агентов
        ├── app/roles.py         библиотека ролей
        ├── app/templates.py     шаблоны проектов
        ├── app/store.py         JSON-хранилище
        └── app/runner.py        запуск CrewAI в отдельном потоке
                    │
                    ▼
                CrewAI (Agent, Task, Crew, LLM) + event bus
```

Приложение однопроцессное, без внешних сервисов и без сборки фронтенда: `app.js`
подключается как обычный `<script>`, стили — обычный CSS. Зависимости Python —
только то, что нужно CrewAI.

## Модули

| Модуль | Ответственность |
|---|---|
| `config.py` | Пути, настройки по умолчанию, список провайдеров, нормализация имени модели, чтение `.env` |
| `security.py` | Политика путей (`confine`, `web_path`), SSRF-проверка (`check_url`), заголовки безопасности, лимит тела |
| `store.py` | Проекты, настройки, история запусков, индексы, шифрование секретов |
| `secrets.py` | Шифрование ключей: Windows DPAPI, иначе Fernet с локальным ключом |
| `spec.py` | Схема проекта: нормализация, проверки, плейсхолдеры, генерация Python-кода |
| `workspace.py` | Разрешённые корни, проверка служебных каталогов, проводник, папки проектов |
| `tools.py` | Встроенные инструменты, каталог сторонних, установка `crewai-tools` |
| `roles.py` | 12 встроенных ролей + свои, применение к агенту |
| `templates.py` | 4 встроенных сценария + свои шаблоны |
| `runner.py` | Слот запуска, поток выполнения, события, подтверждения, отмена |
| `statuses.py` | Единственный набор терминальных/активных статусов |
| `observability.py` | JSONL-логи, редакция секретов, ретенция |
| `crewai_env.py` | Перенаправление служебных папок CrewAI в `data/`, блокировка импорта |

## Жизненный цикл запуска

1. **Проверка.** `server.POST /api/runs` берёт проект по `crew_id`, нормализует,
   валидирует и при ошибках отвечает `422` с перечнем полей. Inline-спека не
   принимается: у проекта должна быть сохранённая рабочая область.
2. **Постановка.** `RunManager.start` занимает единственный слот. Параллельный
   запуск получает `409`: event bus CrewAI глобальный, два прогона одновременно
   перемешали бы события.
3. **Выполнение.** Поток `run-<id>`:
   - применяет настройки к `os.environ` (ключи провайдеров);
   - проверяет рабочую область политикой и при отказе берёт папку по умолчанию;
   - строит `Agent`/`Task`/`Crew`, поднимает `stream=True` и подписывается на
     события CrewAI;
   - вызывает `crew.kickoff(inputs=…)`.
4. **События.** Каждое событие получает монотонный `seq` и попадает в кольцевой
   буфер (`EventRing`, 12 000 записей). `GET /api/runs/{id}/events` отдаёт SSE с
   `id:` и поддерживает `Last-Event-ID` — переподключение продолжает с места
   разрыва.
5. **Завершение.** Слот освобождается только в `finally`. Отменённый или
   отсоединённый прогон никогда не помечается `completed`.

### Статусы

| Статус | Значение |
|---|---|
| `queued` | создан, поток ещё не начал работу |
| `running` | выполняется |
| `cancelling` | пользователь нажал «Остановить» |
| `force_stopping` | модель/инструмент не реагируют; слот занят до завершения потока |
| `completed` | успешно завершён |
| `failed` | ошибка |
| `cancelled` | отменён или отсоединён |

`TERMINAL = {completed, failed, cancelled, force_stopping}` — используется в трёх
местах: эвикция из памяти, пометка осиротевших при старте, закрытие SSE.

### Отмена и отсоединение

- `cancel()` ставит `cancelled`, будит ожидающие подтверждения и запускает
  watchdog на 12 секунд.
- Watchdog не освобождает слот, а переводит запуск в `force_stopping` — иначе
  новый прогон начал бы писать поверх старого.
- `detach()` освобождает слот немедленно, помечает прогон `abandoned` и запрещает
  ему писать файлы, ходить в сеть и получать ответы по подтверждениям.

## Событийная модель

События (`state.emit`) — единственный канал прогресса: текст модели, вызовы
инструментов, предупреждения, ошибки, подтверждения. Из них же собирается
снимок для истории. Крупные тексты не дублируются: `llm_chunk` не сохраняются,
вместо них — агрегированный `task_text`.

Чекпойнт снимка пишется каждые ~30 секунд или 200 событий, поэтому падение
процесса не теряет весь прогресс.

## Подтверждения

`RunState.ask_permission()` создаёт запрос, событие `permission_request` уходит в
UI, поток ждёт `threading.Event` до 5 минут. Ответ приходит через
`POST /api/runs/{id}/permissions/{req}`.

Область гранта честная:

- запись вне рабочей области — разрешение на **файл**;
- запись внутри при включённом подтверждении — на **папку** (и это написано в окне);
- листинг папки — на эту папку, не на родителя.

Инструменты получают `RunState` при создании, а не через глобальную переменную:
два прогона не могут перепутать адресата.

## Хранение

```
data/
  crews/<id>.json          проект
  runs/<id>.json           снимок запуска (события, результат, токены)
  runs/index.jsonl         индекс истории (компактится)
  roles.json               библиотека ролей
  templates/<key>.json     свои шаблоны
  workspaces/<id>/         рабочая область по умолчанию
  uploads/, outputs/       файлы
  settings.json            настройки, ключи зашифрованы
  logs/app-*.jsonl         запросы и ошибки
```

Запись атомарная: временный файл + `os.replace`. Индекс истории — построчный
журнал, который перезаписывается при превышении порога (500 записей или 1 МБ при
старте), поэтому чтение истории не растёт линейно от её длины.

## Политика путей

Единая точка — `security.confine` и `workspace`:

- `confine(path, root)` — резолвит и проверяет `relative_to`, запрещает NUL;
- `web_path` — только файлы из `web/`, без `..`, `\`, дисков и абсолютных путей;
- `assert_safe_target` — служебные каталоги (Startup, System32, `.ssh`,
  `site-packages`, `app`, `web`, `data/crews`, `data/runs`), проверка по
  **resolved** пути, поэтому симлинк не обходит запрет;
- `authorize_or_default` — политика применяется и при сохранении, и при запуске.

Инструменты дополнительно ограничены рабочей областью: относительные имена
всегда пишутся в неё, абсолютные требуют подтверждения.

## Сетевые инструменты

Встроенный `fetch_url` — под полной политикой: `check_url` (private, loopback,
link-local, reserved, multicast запрещены), до трёх редиректов с повторной
проверкой, таймаут 20 с, чтение ≤ 1,5 МБ.

Сторонние `crewai-tools` работают своим кодом, поэтому:

- файловые и RAG-инструменты удалены из каталога;
- сетевые — выключены по умолчанию и включаются поимённо;
- каждый инструмент оборачивается `guard_network_tool`: проверка URL-аргументов,
  запрет для отсоединённого прогона, подтверждение выхода в сеть и событие
  `tool_network` с хостом.

## Фронтенд

`web/app.js` — один файл без фреймворка: состояние в `state`, рендер через
шаблонные строки, делегирование событий через `data-action`. SSE подключается
`EventSource`; при разрыве — переподключение с `Last-Event-ID`.

Особенности, которые стоит знать при правках:

- токен сессии читается из `<meta name="studio-token">` и добавляется в
  заголовок всех изменяющих запросов;
- автосохранение отложено на 900 мс; у него есть «поколение», чтобы ответ
  старого сохранения не перезаписал более новое изменение (например, сброс
  рабочей области);
- после перезапуска сервера токен меняется — страницу нужно обновить.

## Ограничения

- Один прогон одновременно — сознательное решение (глобальный event bus CrewAI).
- Прогон живёт в процессе приложения: жёсткая изоляция не достигнута, отсюда
  компромиссы вокруг «Отсоединить» и `os.environ`.
- История — JSON, а не SQLite: для локального инструмента этого достаточно, но
  при десятках тысяч запусков стоит перейти на SQLite.
